📦 Основные команды Git для начинающих
Используй этот список как шпаргалку при работе с Git. Команды расположены в порядке типичного рабочего процесса.

0. git init
Инициализирует новый локальный репозиторий Git в текущей папке.
Создаёт скрытую папку .git, где хранятся все данные о версиях файлов.

bash
git init
1. git remote add origin <адрес_репозитория>
Связывает локальный репозиторий с удалённым (например, на GitHub/GitLab).
После этого можно использовать origin как короткое имя для URL репозитория.

bash
git remote add origin https://github.com/username/project.git
⚠️ Выполняется один раз после git init, если не клонируете репозиторий.

2. git clone <репозиторий>
Клонирует удалённый репозиторий на ваш компьютер.
Автоматически создаёт папку, инициализирует .git, и подключает origin.

bash
git clone https://github.com/username/project.git
✅ Это альтернатива git init + git remote add. Обычно используется, если проект уже существует удалённо.

3. .gitignore
Файл, в котором перечислены пути к файлам/папкам, которые не должны отслеживаться Git:
логи, временные файлы, зависимости (node_modules, __pycache__, .env и т.д.).

Пример содержимого:

node_modules/
.env
*.log
.DS_Store
Создайте .gitignore до первого коммита, чтобы не добавлять ненужное.

4. git status
Показывает текущее состояние репозитория:

Какие файлы изменены
Какие добавлены в stage (подготовлены к коммиту)
Какие неотслеживаемые (untracked)
bash
git status
✅ Всегда запускайте перед add и commit, чтобы понимать, что делаете.

5. git add <файлы>
Добавляет указанные файлы в staging area (область подготовки).
Только после этого Git включит изменения в следующий коммит.

bash
git add file.txt               # добавить один файл
git add .                      # добавить все изменения в текущей папке
git add src/                   # добавить всё из папки src
❗ Не добавляет файлы, перечисленные в .gitignore.

6. git diff
Показывает разницу между текущими изменениями в рабочей директории и последним коммитом (или stage).

bash
git diff           # что изменено, но не добавлено в stage
git diff --staged  # что добавлено в stage, но ещё не закоммичено
✅ Полезно проверить изменения перед коммитом.

7. git commit -m "сообщение"
Фиксирует изменения из staging area в истории проекта.
Флаг -m означает "message" — позволяет написать комментарий к коммиту.

bash
git commit -m "Добавил главную страницу"
✅ Коммит — это точка восстановления. Пишите понятные сообщения.

8. git log / git log --oneline
Показывает историю коммитов.

bash
git log                    # полная история
git log --oneline          # кратко: хеш и сообщение
git log --oneline -10      # последние 10 коммитов
✅ Используйте для просмотра, откуда что взялось.

9. git push origin <ветка>
Отправляет ваши коммиты из локальной ветки в удалённый репозиторий.

bash
git push origin main
✅ Выполняйте после коммита, чтобы синхронизировать с облаком (GitHub и т.д.).

10. git pull origin <ветка>
Получает новые коммиты из удалённого репозитория и сливает их с текущей веткой.

bash
git pull origin main
✅ Всегда делайте pull перед началом работы, чтобы быть в курсе изменений.

git pull = git fetch + git merge

11. git branch
Показывает список локальных веток.
Текущая ветка помечена *.

bash
git branch
12. git branch <имя>
Создаёт новую ветку из текущей позиции (обычно из main).

bash
git branch feature/login
13. git checkout <ветка>
Переключается на указанную ветку.

bash
git checkout feature/login
14. git checkout -b <имя>
Создаёт новую ветку и сразу переключается на неё.

bash
git checkout -b feature/login
✅ Стандартный способ начать новую задачу.

15. git merge <ветка>
Сливает указанную ветку в текущую.

bash
git checkout main
git merge feature/login
✅ Используется, чтобы внести изменения из фичи в основную ветку.

16. git branch -d <ветка>
Удаляет локальную ветку после мержа.

bash
git branch -d feature/login
❗ -d не удалит ветку, если есть неслитые изменения. Используйте -D для принудительного удаления (осторожно!).

17. git reset <файл>
Убирает файл из staging area, но сохраняет изменения в рабочей директории.

bash
git reset file.txt
✅ Если случайно добавили файл в add, но не хотите его коммитить.

18. git reset --hard
Опасно! Полностью откатывает всё:

Удаляет все незакоммиченные изменения
Очищает staging area
Возвращает файлы к состоянию последнего коммита
bash
git reset --hard
❗ Потеряете все локальные изменения. Используйте только если уверены.

19. git remote -v
Показывает список подключённых удалённых репозиториев (обычно origin) и их URL.

bash
git remote -v
✅ Полезно проверить, куда вы отправляете push.

20. git fetch
Загружает изменения из удалённого репозитория, но не сливает их.

bash
git fetch
✅ Можно посмотреть, что изменилось, до merge.
git pull = git fetch + git merge

🔄 Типичный рабочий процесс
bash
# 1. Начало: клонируем (или инициализируем)
git clone https://github.com/username/project.git

# 2. Создаём ветку для новой задачи
git checkout -b feature/header

# 3. Работаем, добавляем файлы
git status
git add .
git diff --staged

# 4. Фиксируем
git commit -m "Добавил шапку сайта"

# 5. Получаем актуальные изменения
git checkout main
git pull origin main

# 6. Возвращаемся в свою ветку и мержим актуальное main
git checkout feature/header
git merge main

# 7. Отправляем
git push origin feature/header

# 8. После ревью — мержим в main (на GitHub/GitLab или локально)
git checkout main
git merge feature/header
git push origin main

# 9. Удаляем ветку (локально)
git branch -d feature/header
