# 📦 Полное руководство по Git для начинающих

Это руководство поможет вам освоить основные команды Git и понять принципы работы с системой контроля версий. Команды расположены в порядке типичного рабочего процесса.

## ⚙️ Инициализация и подключение репозитория

### 1. `git init`

Инициализирует новый локальный репозиторий Git в текущей папке. Создаёт скрытую папку `.git`, где хранятся все данные о версиях файлов.

```bash
git init
```

⚠️ Выполняется один раз при создании нового проекта, если вы не клонируете существующий репозиторий.

---

### 2. `git clone <ссылка_на_репозиторий>`

Клонирует удалённый репозиторий на ваш компьютер. Создаёт папку, инициализирует `.git`, и подключает `origin`.

```bash
git clone https://github.com/username/repository.git
```

✅ Альтернатива `git init + git remote add`. Используется чаще, если проект уже существует удалённо.

---

### 3. `git remote add origin <ссылка_на_репозиторий>`

Связывает локальный репозиторий с удалённым (например, GitHub или GitLab).

```bash
git remote add origin https://github.com/username/repository.git
```

⚠️ Выполняется один раз после `git init`, если не клонируете репозиторий.

---

## 🧹 Игнорирование файлов

### 4. `.gitignore`

Файл, в котором перечислены файлы и папки, которые Git не должен отслеживать: логи, временные файлы, зависимости и т.д.

Пример содержимого `.gitignore`:

```gitignore
node_modules/
.env
*.log
.DS_Store
coverage/
dist/
build/
```

✅ Создайте `.gitignore` **до первого коммита**, чтобы избежать добавления ненужных файлов.

---

## 🔍 Проверка состояния

### 5. `git status`

Показывает текущее состояние репозитория:

- Изменённые файлы
- Добавленные в stage (подготовлены к коммиту)
- Неотслеживаемые файлы

```bash
git status
```

✅ Запускайте перед `add` и `commit`, чтобы понимать, что именно меняете.

---

## ➕ Добавление изменений

### 6. `git add <файлы>`

Добавляет файлы в **staging area** (область подготовки).

```bash
git add file.txt  # добавить один файл
```

```bash
git add .  # добавить все изменения
```

```bash
git add src/  # добавить всё из папки src
```

```bash
git add *.js  # добавить все JS файлы
```

❗ Не добавляет файлы из `.gitignore`.

---

## 🧾 Просмотр изменений

### 7. `git diff`

Показывает различия между текущими изменениями и последним коммитом.

```bash
git diff  # показать неотслеживаемые изменения (не добавленные в stage)
```

```bash
git diff --staged  # показать изменения, которые будут закоммичены
```

```bash
git diff HEAD~1  # сравнить с предыдущим коммитом
```

📝 Чтобы выйти из просмотра в терминале, нажмите `q` (убедитесь, что используете английскую раскладку).

✅ Проверяйте перед коммитом, чтобы убедиться в правильности изменений.

---

## 💾 Сохранение изменений

### 8. `git commit -m "сообщение"`

Фиксирует подготовленные изменения с пояснением.

```bash
git commit -m "Добавил шапку сайта"
```

```bash
git commit -am "Сообщение"  # добавить и закоммитить изменённые файлы за один раз
```

✅ Каждый коммит — точка восстановления. Пишите понятные и информативные сообщения.

---

## 🕓 История изменений

### 9. `git log`

Показывает историю коммитов.

```bash
git log  # подробная история
```

```bash
git log --oneline  # краткая форма
```

```bash
git log --oneline -10  # последние 10 коммитов
```

```bash
git log --graph  # визуализировать историю ветвлений
```

✅ Помогает понять, кто и что изменил.

---

## ☁️ Работа с удалённым репозиторием

### 10. `git push origin <ветка>`

Отправляет локальные коммиты в удалённый репозиторий.

```bash
git push origin main
```

```bash
git push origin feature/login --set-upstream  # установить связь между локальной и удаленной веткой
```

✅ Выполняйте после `commit`, чтобы синхронизировать проект.

---

### 11. `git pull origin <ветка>`

Получает новые коммиты из удалённого репозитория и сливает их с текущей веткой.

```bash
git pull origin main
```

✅ Делайте `pull` перед началом работы, чтобы быть в курсе изменений.  
`git pull = git fetch + git merge`

---

## 🌿 Работа с ветками

### 12. `git branch`

Показывает список локальных веток. Текущая отмечена `*`.

```bash
git branch
```

```bash
git branch -a  # показать все ветки (локальные и удалённые)
```

---

### 13. `git branch <имя>`

Создаёт новую ветку из текущей.

```bash
git branch feature/login
```

---

### 14. `git checkout <ветка>`

Переключается на другую ветку.

```bash
git checkout feature/login
```

---

### 15. `git checkout -b <имя>`

Создаёт ветку и сразу переключается в неё.

```bash
git checkout -b feature/login
```

✅ Удобно начинать новую задачу в отдельной ветке.

---

### 16. `git switch <ветка>`

Современная альтернатива `git checkout`, используется только для переключения между ветками.

```bash
git switch feature/login
```

---

### 17. `git switch -c <имя>`

Создаёт новую ветку и переключается на неё (современный способ).

```bash
git switch -c feature/login
```

---

### 18. `git merge <ветка>`

Сливает указанную ветку в текущую.

```bash
git checkout main
git merge feature/login
```

✅ Используется при завершении задачи для объединения изменений.

---

### 19. `git branch -d <ветка>`

Удаляет локальную ветку после слияния.

```bash
git branch -d feature/login
```

```bash
git branch -D feature/login  # принудительно удалить ветку, даже если она не слита
```

## 🔄 Управление изменениями

### 20. `git reset <файл>` / `git reset` / `git restore --staged .`

`git reset` - убирает **все** файлы из staging area, но не трогает сами изменения в рабочей директории.  
Полезно, если хотите очистить stage перед тем, как создать новую ветку и добавить файлы уже в неё.

```bash
git reset  # сбросить все файлы из stage
```

```bash
git restore --staged .  # современный синтаксис для сброса всех файлов из stage
```

```bash
git reset file.txt  # убрать конкретный файл из stage
```

✅ Используйте, если случайно сделали `git add`.

---

### 21. `git restore <файл>`

Восстанавливает файл из последнего коммита (отменяет локальные изменения).

```bash
git restore file.txt  # отменить изменения в одном файле
```

```bash
git restore .  # отменить все локальные изменения
```

⚠️ Опасная команда! Все локальные изменения в файлах будут потеряны.

---

### 22. `git reset --hard`

**Очень опасная команда!** Полностью откатывает все незакоммиченные изменения и сбрасывает историю до указанного коммита.

```bash
git reset --hard  # откатить все несохраненные изменения
```

```bash
git reset --hard HEAD~1  # откатить к предыдущему коммиту
```

❗ Все локальные изменения будут потеряны без возможности восстановления.

---

## 🌐 Работа с удалёнными ссылками

### 23. `git remote -v`

Показывает подключённые удалённые репозитории и их URL.

```bash
git remote -v
```

✅ Полезно проверить, куда будет происходить `push`.

---

### 24. `git fetch`

Загружает изменения из удалённого репозитория без слияния.

```bash
git fetch
```

```bash
git fetch origin main  # получить обновления конкретной ветки
```

✅ Позволяет просмотреть изменения перед `merge`.  
`git pull = git fetch + git merge`

## 🔄 Типичный рабочий процесс

Ниже представлен стандартный рабочий процесс при работе с Git:

1. **Клонируем проект** (или инициализируем новый)

```bash
git clone https://github.com/username/project.git
```

2. **Создаём новую ветку** для выполнения задачи

```bash
git checkout -b feature/header
```

3. **Работаем над задачей** и добавляем изменения

```bash
git status
git add .
git diff --staged
```

4. **Сохраняем изменения**

```bash
git commit -m "Добавил шапку сайта"
```

5. **Получаем обновления** из основной ветки

```bash
git checkout main
git pull origin main
```

6. **Мержим актуальное состояние main в свою ветку**

```bash
git checkout feature/header
git merge main
```

7. **Отправляем изменения** в удалённый репозиторий

```bash
git push origin feature/header
```

8. **После ревью** - мержим в main через интерфейс GitHub/GitLab или командой

```bash
git checkout main
git merge feature/header
git push origin main
```

9. **Удаляем использованную ветку**

```bash
git branch -d feature/header
```

## 🛠️ Полезные команды и практики

### Проверка конфигурации

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "your.email@example.com"
```

### Отмена последнего коммита (не отправленного в remote)

```bash
git reset --soft HEAD~1  # отменить последний коммит, но сохранить изменения
```

### Игнорирование уже отслеживаемых файлов

```bash
git rm --cached filename  # перестать отслеживать файл, но оставить его в проекте
```

### Быстрая проверка изменений

```bash
git stash  # временно сохранить изменения
git stash pop  # вернуть последние сохраненные изменения
```
